## Повторение

```bash
python -m pip install --require-hashes -r requirements-dev.txt
python manage.py test --settings=config.test_settings
python manage.py makemigrations --check --dry-run --settings=config.test_settings
ruff check .
pip-audit --require-hashes -r requirements.txt --progress-spinner off
python -m playwright install chromium
python scripts/browser_smoke.py

docker build -t homeinventory:test .
sh scripts/docker_smoke.sh homeinventory:test
```

Браузерный скрипт сам создаёт временные SQLite/media, пользователей и локальный сервер; существующая база не используется. Внешние изображения, proxy CA bypass и камера-stub не требуются для QR PNG smoke. Для managed среды может потребоваться корректный доверенный CA при скачивании образов/пакетов; проверка TLS не отключается.

Для PostgreSQL задать `DATABASE_URL` тестового локального сервера и `DB_SSLMODE=disable` только для этой изолированной проверки, затем выполнить тот же test runner. В production внешняя PostgreSQL по умолчанию проверяет сертификат и имя сервера.

## Границы доказательств

- QR-код декодирован из файла; физическая камера Android/iOS, принтер и реальная бумажная этикетка не проверены.
- Автоматическая проверка доступности не заменяет ручную работу со screen reader.
- Внешний Railway, рабочая PostgreSQL пользователя, инфраструктурное TLS и внешнее backup storage не обновлялись.
- SQLite backup содержит учётные записи и личные файлы; файлы проверок и резервные копии не включаются в Git.
- Пилоты, спрос, AI/OCR, полноценный offline и лицензия проекта остаются отдельными этапами согласно [дорожной карте](ROADMAP.md).
