# Изменения по аудиту HomeInventory

Основание — приложенный владельцем `homeinventory.pdf` и аудит исходной версии `cf6028e978a52565e5571562a22cefe4951697a0` от 12 ноября 2026 года. PDF содержит описание старых результатов и рекомендации; утверждение исходного отчёта «файлы не изменены» относится к тому этапу аудита, а не к этой модернизации.

Этот документ сопоставляет рекомендации с областью решения и требуемой проверкой. Он не объявляет завершёнными полевые испытания, реальную работу стороннего deployment или гипотезы будущего спроса.

## Безопасность и надёжность

| Находка | Область исправления | Что проверять |
|---|---|---|
| S1: публичный каталог и CSV | Авторизация, Workspace/Membership, ограниченные пространством запросы и формы, приватная выдача media | Anonymous, пользователь другого пространства, подставленный ID, экспорт, API, файл и admin |
| S2: has_delete_permission=True | Штатные права Django и дополнительные роли пространства | Staff с view без delete не удаляет объект и не вызывает массовое удаление |
| S3: production fallback и широкие origins | Безопасный SECRET_KEY, точные hosts/origins, HTTPS origin, явное доверие proxy, без подавления проверок | Запуск без ключа отклоняется; deploy check и реальный proxy проверяются отдельно |
| S4: старые зависимости | Django 5.2 LTS, согласованные библиотеки и закреплённые хэши транзитивных зависимостей | Установка с хэшами, regression suite, миграции, повторный dependency audit |
| S5: неподключённая защита входа | django-axes с хранилищем в БД, документированная политика IP | Реальные неверные попытки блокируются; внешний X-Forwarded-For не даёт обход |
| S6: формулы CSV | Единая безопасная сериализация недоверенных текстовых ячеек | `=`, `+`, `-`, `@`, управляющие символы в пользовательском и admin-экспорте |
| S7: innerHTML сканера | Безопасные DOM API и проверка origin/пути QR; отсутствие слепого обращения к несуществующему API | Неверный, внешний, отозванный и недоступный код; ошибки камеры и сети |

Шифрование секретов в инфраструктуре, конфигурация edge limiter и резервирование конкретного облачного провайдера остаются обязанностями установки. Ограничение входа не означает наличие MFA: 2FA/passkeys не заявлены как реализованные. Изменение числового ID на UUID не считается заменой проверки доступа.

## Пользовательские сценарии

| Находка / рекомендация | Решение | Проверка и ограничения |
|---|---|---|
| QR на localhost, отсутствующий API | Канонический PUBLIC_BASE_URL и стабильные label-маршруты, генерация QR по запросу | Другая машина/телефон должны видеть указанный origin; физическая камера требует отдельного испытания |
| Ошибка `/api/` | Согласованный ограниченный API без ссылки на отсутствующий ADMIN_URL | Авторизация, корректный JSON, отсутствие лишних полей |
| Кириллица и регистр | Нормализованное поисковое поле | «Паспорт» по «паспорт», SQLite и заявленная PostgreSQL |
| Неверные фильтры → 500 | Валидируемые параметры и ограниченная выдача | Некорректный ID не вызывает server error, фильтры сохраняются в UI |
| Пустой/сбойный QR ломает Item | Отсутствие файлового побочного эффекта в save и устойчивое состояние карточки | Вещь читается без сохранённого QR и при ошибке генерации |
| N+1 и бесконечная выдача | select_related, пагинация и контроль числа запросов | Набор 50/100 записей не даёт линейный рост SQL из-за связей |
| Нет модели коробки | Контейнеры и места внутри пространства, история перемещений | Перемещение коробки, целостность связей, конфликт конкурентной правки |
| Добавление через admin | Пользовательские формы вещей, контейнеров и мест | Обычный редактор работает без staff-аккаунта |
| Нулевая цена и неполные состояния | Различение 0 и None, доступные пустые состояния | Карточка с нулевой ценой, отсутствующим фото/QR и без результата поиска |
| Приватное постоянное media | Настраиваемый MEDIA_ROOT и защищённая выдача | DEBUG=False, restart/redeploy, чужой URL, лимиты изображения и удаление EXIF |
| Нет переносимости | Каталожный ZIP с фотографиями, безопасный импорт в новое пространство, отдельный operational backup/restore | Предпросмотр/подтверждение, ограничения архива, path traversal, контрольные суммы и восстановление |
| Выдача предмета | Loan и операции выдачи/возврата | Одна активная выдача, принадлежность участника пространству, повторный возврат |
| Совместное пользование | Явная отзываемая публичная карточка | Только публичные название/описание; без личных заметок, media и места хранения |

Перенос каталога и полное восстановление установки различаются. Каталожный ZIP не переносит пользователей, memberships, текущие выдачи и журнал; новая копия получает новые label ID и требует новых этикеток. Полная копия SQLite и media сохраняет эти данные и предназначена доверенному оператору.

## Проверки

Штатный запуск:

```bash
python manage.py test --settings=config.test_settings
python manage.py makemigrations --check --dry-run --settings=config.test_settings
```

Дополнительно выполняются dependency audit, линтер, production checks, сборка static, browser smoke и проверки выбранной СУБД. В исходном репозитории было 0 тестов; старые цифры «28: 12 passed, 16 failed» описывали внешний аудиторский набор до изменений и не являются текущими результатами проекта.

Результаты конкретного запуска следует фиксировать с commit SHA и используемыми командами. Наличие теста в репозитории не означает, что он был запущен. CI-конфигурация не означает успешный запуск удалённого GitHub Actions.

## Что не следует объявлять завершённым

- Пилоты с семьями и мастерскими, интервью, успешность поиска и доказанный спрос.
- Работа камеры настоящего Android/iOS-устройства, печатной этикетки и выбранного принтера без полевой проверки.
- Реальный Railway deployment, внешний PostgreSQL и внешнее backup storage без проверки этой установки.
- Полный офлайн-режим/PWA-синхронизация, AI/OCR, автоматические рассылки и складские остатки. В PDF это условные функции после подтверждения необходимости.
- Готовая публичная библиотека вещей: технической карточки недостаточно без правил группы, модерации и процесса спорных выдач.
- Выбор лицензии от имени владельца. Ложный исторический MIT badge удаляется, но новая лицензия автоматически не назначается.
