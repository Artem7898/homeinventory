# HomeInventory

HomeInventory помогает людям находить вещи, понимать, где они находятся и кому переданы. Один каталог можно использовать дома, в мастерской или в небольшой группе совместного пользования.

Проект построен на Django 5.2 LTS и Python 3.14. Основные сущности — приватное пространство, его участники, места хранения, контейнеры и вещи. Публичная карточка создаётся отдельно: публикация вещи не должна раскрывать остальной инвентарь.

## Что можно делать

- Вести отдельные пространства для дома, мастерской или сообщества с ролями владельца, редактора и наблюдателя.
- Добавлять вещи и фотографии через пользовательские формы, распределять их по местам и контейнерам.
- Искать вещи, фильтровать каталог, печатать этикетки и открывать разрешённые карточки по QR.
- Перемещать контейнеры и вещи с историей операций.
- Регистрировать выдачу предмета участнику и его возврат.
- Публиковать только специально выбранные название и описание отдельной вещи, затем отзывать публикацию.
- Выгружать CSV и переносимый архив каталога пространства. Он сохраняет вещи и фотографии, но не переносит пользователей, роли, выдачи и журнал операций; для полной копии установки используется отдельный backup. Архив с файлами требуется хранить как конфиденциальные данные.

Сервис не является бухгалтерской системой, профессиональной системой складских остатков или сервисом страховой оценки. AI, полный офлайн-режим и автоматические уведомления пока не заявлены как готовые возможности.

## Локальный запуск

Нужен Python 3.14. Для PostgreSQL также нужны его клиентские библиотеки и заголовки, используемые при установке `psycopg2`; для локального личного каталога доступен SQLite.

```bash
git clone https://github.com/Artem7898/homeinventory.git
cd homeinventory
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.txt
cp .env.example .env
```

В `.env` включите `DEBUG=True` для локальной разработки. Для QR на другом устройстве укажите доступный ему адрес в `PUBLIC_BASE_URL`: `localhost` относится к устройству, которое открывает ссылку. Для камеры в браузере на телефоне обычно нужен HTTPS; локальный запуск сам по себе не предоставляет публичный HTTPS-адрес.

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py collectstatic --noinput
python manage.py runserver 127.0.0.1:8000
```

Откройте локальный сервер, войдите и создайте пространство. Открытой регистрации нет: новые учётные записи создаёт администратор. Владелец пространства добавляет существующих пользователей и назначает роли. Для повседневной работы не требуется давать пользователю staff-доступ к админке.

Если используется `uv`, эквивалент установки зависимостей:

```bash
uv venv --python 3.14 .venv
uv pip sync --python .venv/bin/python --require-hashes requirements.txt
```

## Обновление существующей установки

Перед миграциями сохраните согласованную резервную копию базы **и** media и проверьте восстановление на отдельной копии. Не запускайте миграции на единственном экземпляре данных без копии. Полный порядок обновления описан в [руководстве](docs/DEPLOYMENT.md).

Старые вещи, категории и места переносятся в закрытое пространство «Импортированные данные». Миграция не назначает владельца случайному пользователю. Сначала оно доступно суперпользователю; дальнейшее владение назначается явно.

## Проверки перед отправкой изменений

```bash
python manage.py test --settings=config.test_settings
python manage.py makemigrations --check --dry-run --settings=config.test_settings
```

Отдельно проверяйте production-конфигурацию с настоящими безопасными настройками:

```bash
python manage.py check --deploy
```

Успех `check` не заменяет тесты. Не подавляйте предупреждения только ради успешного результата. Браузерные сценарии и проверка зависимостей описаны в CI и [CONTRIBUTING.md](CONTRIBUTING.md). Проверка эмуляции QR не заменяет проверку физической камеры и печатной этикетки.

## Безопасное размещение

Для production необходимы отдельный `SECRET_KEY`, точные `ALLOWED_HOSTS` и `CSRF_TRUSTED_ORIGINS`, канонический HTTPS-адрес `PUBLIC_BASE_URL` и постоянное приватное хранилище. `.env`, база, фотографии и резервные копии не должны попадать в Git. Reverse proxy не должен раздавать `media/` в обход проверки доступа приложения.

Веб-процесс не заменяет release-миграции и резервное копирование. Подробности: [DEPLOYMENT.md](docs/DEPLOYMENT.md).
