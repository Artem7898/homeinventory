# Участие в HomeInventory

Цель проекта — помогать людям находить вещи, поддерживать актуальность мест хранения и безопасно пользоваться предметами совместно. Новая функция должна иметь понятный пользовательский сценарий и проверяемый результат.

## Работа с изменениями

Используйте отдельную ветку и небольшие изменения с понятной областью. В облачной задаче checkout уже изолирован; дополнительный Git worktree не нужен без явной необходимости или запроса. Не включайте в коммит `.env`, базы данных, media, резервные копии, виртуальные окружения, токены и личные данные.

В описании изменения укажите проблему, новое поведение, проверенные команды и оставшиеся ограничения. Не представляйте запланированную функцию или нулевой запуск тестов как проверенную возможность.

## Настройка

Следуйте [README.md](README.md). Runtime-зависимости установлены из `requirements.txt` с хэшами. Меняйте исходный список зависимостей и пересобирайте lock-файл; не удаляйте проверки TLS, подписи или ожидаемые хэши, чтобы пройти установку.

Перед изменениями схемы сохраните копию данных. Миграции должны сохранять старые вещи и файлы и не назначать доступ произвольному пользователю.

## Проверки

Минимальные команды:

```bash
python manage.py test --settings=config.test_settings
python manage.py makemigrations --check --dry-run --settings=config.test_settings
```

Production-настройки проверяются отдельно с корректными переменными окружения:

```bash
python manage.py check --deploy
python manage.py collectstatic --noinput
```

Следуйте workflow CI для линтера и dependency audit. Проверка безопасности пакетов сопоставляет установленные версии с advisory; достижимость конкретной уязвимости требует отдельного анализа. Не скрывайте предупреждения и не переводите реальные регрессии в `expectedFailure` для получения зелёного статуса.

Для изменений доступа проверяйте анонимного пользователя, наблюдателя, редактора, владельца и пользователя другого пространства. Проверяйте прямые URL, API, экспорт, медиа, формы, admin и подставленные внешние ключи. UUID не заменяет авторизацию.

Для файлов и архивов нужны проверки предельного размера, формата, повреждённых файлов, path traversal, повторного импорта и очистки после сбоя. Для QR — стабильный URL, отказ камеры, неправильный/внешний код и отсутствие доступа. Для поиска — кириллица и регистр на каждой поддерживаемой СУБД.

Изменения интерфейса проверяйте на узком экране, с клавиатурой, при увеличении и с осмысленными подписями полей. Автоматическая проверка доступности не заменяет ручную. Эмуляция браузера не подтверждает работу камеры настоящего телефона.

## Сообщения о проблемах

Укажите шаги воспроизведения, ожидаемое поведение, версию и обезличенный вывод. Не прикладывайте секреты, полный архив имущества, адреса хранения, фотографии документов или резервную копию базы. Для потенциальной уязвимости сначала согласуйте с владельцем приватный канал; не публикуйте реальные персональные данные как доказательство.
